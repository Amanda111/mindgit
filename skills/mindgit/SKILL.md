# Mindgit 产品导图

产品导图是一个普通的 Markdown 文件（默认 `mindmap.md`），git 记录它的每个版本。人可以在 Mindgit 画布上改，你直接改这个文件，两边会自动同步。

## 文件格式

- `# 标题` 是导图中心（产品名），只有一个。
- `##`、`###` 等标题和列表缩进构成层级。列表缩进用 2 个空格。
- 状态标签写在节点文字后面：`` `[待开发]` `` `` `[进行中]` `` `` `[完成]` `` `` `[搁置]` ``。也认 `- [ ]` / `- [x]` 勾选框。
- 优先级标签：`` `[P0]` `` `` `[P1]` `` `` `[P2]` ``，放在状态标签前面。
- 图片：在节点那一行末尾写 `![说明](assets/文件名.png)`，或者在节点下一行单独写一行图片。图片放在导图同目录的 `assets/` 里。

示例：

```markdown
# 记账 App

## 功能模块
### 记一笔 `[P0]` `[进行中]`
- 金额键盘 `[完成]` ![键盘草图](assets/keyboard.png)
- 分类选择 `[进行中]`
- 拍照识别小票 `[待开发]`
```

## 改导图的规矩

1. 先读懂再改：用 `node "${CLAUDE_PLUGIN_ROOT}/bin/mindgit.js" summary <文件>` 看进度、模块和最近一次的变化，比读全文省事。要改具体节点时再读文件。
2. 只改相关的行，保留原有的写法、空行、emoji 和 frontmatter。不要整篇重写或重新排版。
3. 状态要如实：只有真的做完了才标 `[完成]`。一个模块下所有子任务都完成时，把模块也改成 `[完成]`；有任何子任务在做，模块是 `[进行中]`。
4. 节点文字要短，一个节点一件事。细节拆成子节点，不要写成长段落。
5. 改名会让历史对比把它算成“删除 + 新增”，没必要就别改名。
6. 完成一组相关改动后提交一次：`git add <导图文件> assets && git commit -m "<中文说明改了什么>"`。提交信息写清楚改了什么，例如“登录模块：短信验证完成，新增微信登录”。用户没要求时不要 push。
7. 用户在画布上的改动会直接写进文件，所以改之前重新读一遍文件，别用旧内容覆盖。

## 可用命令

- `/mindgit:open` 打开可编辑画布（本地服务，双向同步）
- `/mindgit:status` 汇报进度
- `/mindgit:render` 生成单文件 HTML，可以发给别人看
- `/mindgit:init` 新建导图
- `/mindgit:commit` 检查导图改动并提交
